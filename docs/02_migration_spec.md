# 2. 移行仕様：入庫・出庫

## 2.1 対象と移行先

| 項目 | 移行元 | 移行先 |
|---|---|---|
| 画面 | `unitEntradaMat`（入庫）, `unitSaidaMat`（出庫） | Vue.js 3 の 1 画面（入出庫登録・在庫一覧・履歴） |
| ロジック | ボタンイベント内 | Spring Boot（Java 17）の `StockMovementService` |
| DB | Paradox `Estoque`, `Entrada`, `Saida` | PostgreSQL `item`, `stock_movement`（Flyway で管理） |

## 2.2 要件

| ID | 要件 | 旧ルール |
|---|---|---|
| R1 | 入庫を登録すると在庫数が増え、区分 `E` の履歴が残る | `BtnGravarClick`（入庫） |
| R2 | 出庫を登録すると在庫数が減り、区分 `S` の履歴が残る | `BtnGravarClick`（出庫） |
| R3 | 在庫数を超える出庫は拒否し、在庫も履歴も変えない | `dbQuantExit`（強化：サーバー側で必ずチェック） |
| R4 | 未登録の品目コードは拒否する | `dbCodMercExit` |
| R5 | 数量は 0 より大きい値。品目コード・担当者は必須 | 画面の必須チェック |
| R6 | 履歴の保存と在庫数の更新は同時に確定する（片方だけにならない） | 新規（1.4 の問題 1） |
| R7 | 同時に出庫しても在庫がマイナスにならない | 新規（1.4 の問題 3） |
| R8 | 最低在庫を下回る品目が一覧でわかる | 在庫帳票・品目画面 |

## 2.3 設計

- **API**
  - `GET /api/items`：在庫一覧（`belowMinimum` フラグ付き）
  - `POST /api/movements`：入出庫の登録。成功は 201、未登録コードは 404、在庫不足は 422、入力エラーは 400
  - `GET /api/movements?itemCode=`：入出庫履歴（最新 100 件）
- **トランザクション**：品目行を `SELECT ... FOR UPDATE` でロックし、在庫数の更新と履歴の追加を 1 トランザクションで行う（R6, R7）。
- **数量**：`NUMERIC(14,3)` と `BigDecimal` で扱う（1.4 の問題 4）。
- **区分コード**：DB には旧システムと同じ `E` / `S` を保存し、データ移行時の対応をそのままにする。API では `IN` / `OUT`。
- **画面**：画面側でも在庫不足などを先にチェックし、最終判断はサーバーで行う。
